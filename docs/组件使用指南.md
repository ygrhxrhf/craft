## 2. 新增一个组件的标准写法

按仓库现状收敛出的模板（`export function` 86 处 vs `export default` 1 处——后者只有 `editor/extensions/whiteboard-sync-canvas.tsx:13`）：

```tsx
import { cn } from 'cn'

interface WidgetProps {
  open: boolean
  onClose: () => void
  className?: string
}

export function Widget({ open, onClose, className }: WidgetProps) {
  return <div data-slot="widget" className={cn('rounded-lg border border-input', className)} />
}
```

五条落地的约定：

1. **props 类型一律 `interface <组件名>Props` 写在函数上方**。实跑计数：`interface XProps` **62** 处、`type XProps =` 仅 **2** 处，且那两处是 TipTap 的 `SuggestionProps`（`editor/extensions/emoji-suggestion.tsx:10`、`editor/slash-menu/SlashCommandExtension.ts:10`），不是 React props。**从不写裸 `interface Props`**（计数 0）。内联匿名形 `({a, b}: {a: A})` 存在 37 处，集中在 ui 层与极小组件——**新代码别选这条**。
2. **`data-slot="<kebab-name>"`**：28 个 ui 文件里 27 个都带，是这个库给样式与测试留的锚点（`ui/button.tsx:51`、`ui/input.tsx:9`）。
3. **className 组装只走一个出口**：`cn(...)`。有变体时用 cva——但 cva 只占 ui 层的 **6/28**（`badge`、`button`、`input-group`、`navigation-menu`、`tabs`、`toggle`），其余 22 个是 `Primitive.X.Props` 透传＋普通 props。**别给没有变体的组件硬加 cva**。
4. **透传优先于自定义**：ui 层有 **96** 处把 props 写成 `某个Primitive.X.Props`，即"官方 props ＋ 极小本地扩展"。本地扩展的写法见 `ui/dialog.tsx:42`（`DialogPrimitive.Popup.Props & { showCloseButton?: boolean }`）。
5. **变体不靠顺序、靠 token**：`ui/button.tsx:5` 的 cva 基串＋`variants.variant`/`variants.size`＋`defaultVariants`，最后 `ui/button.tsx:52` 一行 `cn(buttonVariants({ variant, size, className }))` 收尾。

## 5. 数据与状态：组件不碰数据库

- **通路只有三条**：Server Component ＋ Server Action ＋ Prisma 8。**没有 tRPC**（`src/server` 不存在、`package.json` 无 trpc）、没有 React Query／SWR。
- 页面模式照抄 `src/app/(app)/documents/page.tsx:1`：`async function` → `await auth()` → 未登录 `redirect('/login')` → `await Promise.all([...actions])` → 把纯数据往下传给（可客户端化的）展示组件。**组件里永不 import `@/prisma/db`**（该 import 的 35 个持有者全在 actions／lib 侧）。
- `'use client'`：**125 个文件**（`src/components` 101／`src/app` 20）；`'use server'`：33 个文件，与 `src/actions/` 下 33 个非测试文件严格一一对应。
- 鉴权在 action 里做：`src/actions/document/get.ts:5` 的 `requireUserId()` ＋ `resolveDocumentAccess()`，回参套 `AuthorizedDocument`（同文件 L9）。**组件不要自己再判一遍权限**，把 action 给的 `role` 往下传即可。
- `src/prisma/db.ts:6`—`12` 那段 `require`／`globalThis` 绕路是**故意的**（注释写明：避免 middleware→auth 链上的 Turbopack Edge 静态检查看见 `fs`/`path`）。**别"清理"它。**
- **Zustand 只有 5 个 store**，全在 `src/lib/store/`，都用 `create` 于第 1 行：`use-sidebar-store`、`use-sync-store`、`use-command-palette-store`、`use-settings-store`、`use-ai-bubble-store`。消费规则（照现状）：组件里**一律用选择器形式** `useSidebarStore((s) => s.toggleMobileNav)`（`app/AppPageHeader.tsx:17`、`editor/DocumentEditor.tsx:51`）；**React 之外**用 `.getState()`（`providers/MetadataSyncProvider.tsx:47` → `useSidebarStore.getState().bumpTree()`）；不变量留在 setter 里（`use-sidebar-store.ts:27` 的 `Math.max(200, Math.min(400, width))`），不要在调用方补夹取。`useSyncExternalStore` **不是** Zustand 的通路，全仓只用于 `src/lib/use-is-mobile.ts:36` 的 matchMedia 手写订阅。

- Yjs 只被 **3 个文件**触碰：`editor/Editor.tsx`、`src/lib/collaboration/use-collab-session.ts`、`src/lib/sync/changes.ts`（后两者是同步/持久化侧）。`Editor` 的导入者也只有 2 个（`editor/DocumentEditor.tsx:5`、`share/SharedDocView.tsx:4`）。**面窄、爆炸半径是全部。**

## 7. 提交前跑什么

`package.json:4` 的脚本：`dev`／`dev:collab`／`dev:tldraw-sync`／`build`／`start`／`lint`（=`eslint`）／`test`（=`vitest run`）／`test:e2e`（=`playwright test`）／`contract:emit`。**没有 `typecheck` 脚本。**

```bash
npm run lint && npm test && npm run build     # CI quality job 的核心三步
npx tsc -p tsconfig.json --noEmit --incremental false   # 本次实测 0 error
```

- CI 门禁见 `.github/workflows/ci.yml:36`（`prisma contract emit` → `db migrate` → `db verify` → `lint` → `test` → `build`），`e2e` job 依赖它且**从不判视觉**（L83 是 `--update-snapshots`，因为基线文件名带 `-win32`，Linux runner 无可比物）。
- ⚠️ **新 worktree 里 `tsc` 会报一批 `LayoutProps` 缺失的假错**——`tsconfig.json:32` 把 `.next/types/**` 与 `.next/dev/types/**` 纳进 include，干净树里这些生成物不存在。正确处置是先 `npx next typegen`（或跑一次 `dev`／`build`），**不是改源码**。
- 不要在 `next dev` 运行时 `npm run build`（会覆盖 `.next`、把在跑的 dev 变成废器）；跑 e2e 前先确认 3000 端口上那枚是谁。
